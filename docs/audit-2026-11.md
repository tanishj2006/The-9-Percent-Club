# Pre-launch audit: SEO, answer engines, security

**Date:** 11 November 2026 · **Commit audited:** `02d1538` plus the uncommitted
support/feedback work in the tree · **Scope:** the 26 routes in the sitemap,
headers, dependencies, git history, CI.

Everything below was measured on a production build (`next build && next start`)
built with `NEXT_PUBLIC_SITE_URL=https://ninepercent.example`, never on
`next dev`. Lighthouse 12.8.2, mobile preset (simulated Moto G Power, slow 4G),
Playwright's Chromium, on a laptop: one "before" run and two "after" runs
per route (shown where they differ). No performance work is in this diff, so
performance, LCP and TBT movements are run-to-run variation, not
improvements. TBT read higher in both after-runs (60–100 ms against 10–30 ms);
the diff adds no client JavaScript, so treat it as machine load, and let the
Lighthouse CI check (which runs three times per URL) set the real baseline.

Nothing here predicts rankings or citations; it reports what a crawler receives and what the tools measured.

### Things checked that passed

- Open-redirect probes (`//evil.com`, `/\evil.com`, encoded variants, `/en//evil.com`, forged `Host`/`X-Forwarded-Host`): every `Location` stays relative, on this host.
- Every route returns 200 with one `<h1>`, correct `lang`, absolute canonical, hreflang `en`/`hi`/`x-default`, `og:locale` `en_IN`/`hi_IN`, a Twitter card. No heading levels skipped on any page.
- `/` 307s to `/en` (or `/hi` for a Hindi browser); trailing slash 308s; unknown paths 404.
- Source maps are neither generated nor served. Public assets contain no local paths or env names.
- No `NEXT_PUBLIC_` variable holds a secret. `NEXT_PUBLIC_UPI_*` exist only in Vercel env and in the e2e config's test value (`ninepercent.e2e@okexample`). `.env*` is ignored.
- Lockfile is tracked. A clean `npm ci --ignore-scripts` builds and passes vitest: no install script is needed (`@parcel/watcher`, `@swc/core` come via next-intl and are not used in the build).
- Share cards: `image/png`, `public, immutable, max-age=31536000`, static, `dynamicParams = false`.
- On `/en`, every SVG either has `role="img"` with a label or is `aria-hidden`; there are no `<img>` elements (Lighthouse's image-alt audit is "not applicable" on all four measured routes).

## Crawlability fix plan (F-01): implemented

The scenes are the experience; the fix must not change how they look with
JavaScript on. Proposal:

1. **Each chapter page server-renders a short "In numbers" block** after the
   outro: a `<dl>` or a two-column table of the figures the scene reveals, with
   the same values the scene takes from `src/lib/costs.ts`, `drawdown.ts` and
   `sip.ts`, so the numbers cannot drift. Visible to everyone, not hidden: it
   doubles as a recap for readers and a quotable summary for answer engines.
2. **The ch06 curve and ch08 SIP chart get a server-rendered `<table>`** of
   their key points (start, peak, trough, recovery, end), inside a `<details>`
   "See the numbers" like the existing doubts.
3. `e2e/no-js.spec.ts`: each `test.fixme` becomes a real test as its chapter
   lands.

This is new visible copy in both languages, so it needs your wording and
Hindi review. Every new string would be marked for review.

Run on the production URL after the first deploy, and after any change to
headers or routing. Replace `$SITE` with the domain.

- [ ] `curl -sI $SITE/en/04`: CSP, HSTS, nosniff, `X-Frame-Options: DENY`, Referrer-Policy, Permissions-Policy, COOP present; no `X-Powered-By`; no `Link`
